# Что нужно от бэкенда

Сводка от фронтенда на 29.09.2026. Фронт под всё ниже уже готов или работает с временным
обходом — пункт «что сейчас» объясняет какой.

## P0 — блокеры

### 1. CI красный с `c5fd168` — на прод ничего не выкатывается

С коммита «Complete mobile account subscription and push contracts» CI `master` падает
(`c5fd168`, `c5ce79f`, `674df3e`), поэтому CD каждый раз `skipped`. На проде до сих пор нет
refresh-токенов, подписки v2, push и REF-01: `/auth/refresh`, `/v1/me/subscription/offer`,
`/v1/me/referrals` отвечают `404 No route`.

Падает end-to-end smoke удаления аккаунта (PROF-01), 9 проверок:

```
✗ аккаунт удалён без тела
✗ старый токен больше не читает карту
✗ повтор удаления идемпотентен
✗ профиль стал обезличенным tombstone
✗ карта отозвана и отделена от аккаунта
✗ история и подписка удалены
✗ реферальный профиль и начисления удалены
✗ тот же номер создаёт новый аккаунт
✗ у нового аккаунта нет старой карты
```

Run: `gh run view 36560530836 -R Prom-Consulting/cashup_platform --log-failed`.

**Что сейчас.** Фронт на проде с запасными путями: продление подписки идёт старой оплатой по
номеру карты, «Друзья» пишут «программа вот-вот заработает». После зелёного деплоя всё
переключится само.

### 2. Первая покупка подписки v2 без карты — `404`

`GET /v1/me/subscription/offer` и `POST /v1/me/subscription/payments` у человека без карты
отвечают `404 «У вас пока нет карты»` (`card-service` → `me.service.ts`, `billingContext`).
Первую карту поэтому оформляет только старая `POST /v1/public/octopay/subscriptions`
с `months` — а она заводит подписку по месячной модели, не цикл на 90 дней.

**Нужно.** Как в `POST /v1/me/referrals/enroll`: оплата v2 создаёт карту, если её нет, а offer
без карты отвечает `intent: "initial"`. Тогда фронт переведёт первую покупку на цикл 90 дней.

## P1 — важно

### 3. Стабильные коды `error` там, где их ещё нет

Web README требует ветвиться по коду, а не по русскому `message`. Коды есть только у
`SESSION_REPLACED`, `INVALID_REFRESH_TOKEN`, `CARD_FROZEN`, `SUBSCRIPTION_*`,
`PAYMENT_NOT_FOUND`, `ACCOUNT_DELETION_INCOMPLETE`. Фронт пока читает текст здесь:

| Где | Сейчас (текст) | Предлагаемый код |
|---|---|---|
| Вход по коду, `otp.service.ts` | `Invalid OTP` | `OTP_INVALID` |
| | `OTP is missing or expired` | `OTP_EXPIRED` |
| | `429` «слишком много попыток» / «повтор через N с» | `OTP_TOO_MANY_ATTEMPTS` / `OTP_RATE_LIMITED` (+ `retryAfter`) |
| | `503` хранилище кодов | `OTP_UNAVAILABLE` |
| Промокод, `promo-codes.service.ts` | `404` «Сначала получите карту…» | `CARD_REQUIRED` |
| | `404` не найден / выключен | `PROMO_NOT_FOUND` |
| | `409` уже применён | `PROMO_ALREADY_USED` |
| | `400` не та аудитория / истёк / закончился | `PROMO_WRONG_AUDIENCE` / `PROMO_EXPIRED` / `PROMO_EXHAUSTED` |
| Новое заведение | `409` адрес занят | `MERCHANT_SLUG_TAKEN` |
| Добавить клиента | `409` телефон занят | `CUSTOMER_PHONE_TAKEN` |
| Профиль | `409` почта занята | `EMAIL_TAKEN` |
| Потолок процента | `409` до `nextChangeAt` | `COVERAGE_LIMIT_LOCKED` |
| Списание | `409` не хватает баллов | `INSUFFICIENT_POINTS` |

### 4. Публичная цена подписки

Лендинг и форма первой карты показывают `990 сом за 90 дней`, но цену, срок и баланс цикла без
входа взять негде: `platform-settings` — только агентству, offer — только с картой. Сейчас 990
захардкожено во фронте (`VITE_SUBSCRIPTION_PRICE_KGS`) и расходится с админкой при смене цены.

**Нужно.** `GET /v1/public/subscription/offer` без авторизации:
`{ planId, price, currency, cycleDays, cycleBalance }`.

### 5. Телефон аккаунта в профиле

`GET /auth/me` и `GET /auth/me/profile` не отдают телефон (`auth.service.ts`, `getProfile`).
Кабинет клиента поэтому запоминает номер входа в `localStorage`, чтобы подставить его в форму.
**Нужно:** `phone` в `/auth/me/profile`.

### 6. Выход с отзывом refresh-токена

Refresh живёт 30 дней в `localStorage`, а «Выйти» его только стирает на устройстве.
**Нужно:** `POST /auth/logout` (Bearer), гасит refresh этой сессии.

### 7. id платежа в адресе возврата

OctōPAY возвращает на `https://client.loal.kg/payment/return` без номера платежа — фронт
помнит его в `localStorage`. Если оплату завершили в другом браузере (открыли ссылку в
WhatsApp), статус не опросить. **Нужно:** `return_url` с `?paymentId={id}` — фронт уже читает
этот параметр.

## P2 — желательно

### 8. «Cashup» в счетах OctōPAY

Клиент и партнёр видят старое название на странице оплаты (`billing.service.ts`):

- стр. 283 — `Подписка Cashup на N мес.`
- стр. 314 — `Доступ партнёра Cashup на N мес.`
- стр. 332 — получатель `Клиент Cashup`

v2 уже пишет «Подписка Loal» — нужно так же везде.

### 9. Адрес и координаты заведения в витрине

Точки на карте каталога фронт берёт из ссылки 2ГИС («Поделиться» содержит `m=долгота,широта`).
Без такой ссылки у заведения нет точки. **Нужно:** `address`, `lat`, `lng` в
`/admin/v1/merchants/{id}/profile` и в `/v1/public/partners`.

### 10. Обновление каталога при изменениях не из веба

Лендинг кэширует каталог; веб-кабинеты после сохранения витрины зовут
`POST https://loal.kg/api/revalidate-partners`. Если витрину или подписку заведения меняют
мобильное приложение, 1С или агентство напрямую по API — каталог обновится только через минуту.
Можно звать тот же адрес с бэкенда (без тела, без авторизации).

### 11. Промокод клиента в модели v2

`POST /v1/me/promo-code` (legacy) добавляет месяцы старой модели. Нужно решить, что промокод
делает с циклом 90 дней, — фронт пока показывает поле как есть.
