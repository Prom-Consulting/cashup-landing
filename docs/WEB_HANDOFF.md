# Новое для web/frontend

Этот каталог содержит изменения, которые ещё необходимо подключить в web-приложениях и административном кабинете.

Полное поэкранное ТЗ: [`FRONTEND_NEW_FEATURES.md`](FRONTEND_NEW_FEATURES.md). Канонический контракт всех endpoint: [`../../API.md`](../../API.md).

## Обязательные изменения текущего этапа

1. Хранить `accessToken`, `refreshToken` и постоянный `deviceId`.
2. На обычный `401` выполнять один общий `POST /auth/refresh`, сохранять новую пару токенов и один раз повторять исходный запрос.
3. Немедленно завершать локальную сессию только при `INVALID_REFRESH_TOKEN` или `SESSION_REPLACED`.
4. После обновления профиля сохранять оба новых токена из ответа.
5. Не использовать refresh token как Bearer.
6. Для клиентского интерфейса подписки читать цену, срок и баланс из offer; не хардкодить значения.
7. Старые `{ months }` flows оставлять только в тех административных сценариях, где они явно требуются.
8. Поддержать новые стабильные API errors и не ветвиться по русскому `message`.

## Auth refresh

```http
POST /auth/refresh
Content-Type: application/json

{ "refreshToken": "..." }
```

Ответ `200` возвращает `accessToken`, `expiresIn`, `refreshToken`, `refreshExpiresIn`. Параллельные `401` должны объединяться в один refresh-запрос.

## Что не относится к web-пакету

Mobile handoff по PROF-01, SUB-01, CARD-01 и PUSH-01 находится отдельно в [`../mobile/handoff`](../mobile/handoff/README.md). Не нужно копировать mobile-only логику push-token или экранов карты в административный кабинет без отдельной продуктовой задачи.
