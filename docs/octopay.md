# OctoPay: самостоятельная оплата по NFC с баллами CashUp

Документ для фронтенда OctoPay. Дата: 02.10.2026.
CashUp — backend программы лояльности, которая также называется Loal.

## Сценарий покупателя

1. NFC или напечатанный QR открывает `https://payment.octopay.click/s/{publicCode}`.
2. Показать название магазина, филиал и кассу. Покупатель их не выбирает.
3. Покупатель вводит телефон и код из WhatsApp. Код отправляет и проверяет **CashUp**.
4. CashUp проверяет существующую карту и её доступность. Аккаунт OctoPay не создаётся;
   клиент не входит в кабинет OctoPay, его сессия в приложении CashUp не заменяется.
5. Покупатель вводит полную сумму покупки в KGS.
6. Сервер возвращает допустимые проценты, бонусную и банковскую части. Покупатель выбирает вариант.
7. Кнопка «Перейти к оплате» создаёт индивидуальный связанный счёт и открывает `/pay/{invoiceId}`.
8. На странице счёта покупатель явно подтверждает бонусную часть. CashUp резервирует баллы.
9. OctoPay показывает QR/переход в банковское приложение на остаток. До успешного резерва QR не создаётся.
10. После подтверждения банка OctoPay завершает резерв в CashUp. После завершения обеих частей показать «Оплачено».

Управление резервом показывать независимо от результата загрузки банковского QR:
при ошибке банка кнопка «Отменить резерв» должна оставаться доступной.

Пример: 1 000 сом, 20% → 200 баллов и 800 сом через банк.
При 0% нет резерва, банк получает полную сумму. При нулевом банковском остатке
после явного подтверждения выполняются резерв и окончательное списание без QR.

OTP подтверждает владение номером; наличие карты и право списания проверяются отдельно.
Номер телефона сам по себе не является разрешением списывать баллы.

## Что уже находится в OctoPay

- `/s/[code]` — телефон, OTP, сумма и выбор процента.
- `/pay/[invoiceId]` — существующая платёжная страница с поддержкой самостоятельных счетов.
- `/business/checkout-points` — создание и отключение NFC-касс администратором.
- `SelfCheckoutBonus` — подтверждение и отмена резерва на странице счёта.

Для этого сценария использовать `/api/checkout/*`. Существующие
`/api/loal/payer/otp/*` обслуживают прежние счета и не подтверждают новую NFC-сессию.

## Общие правила для фронтенда

Все запросы покупателя идут на текущий origin OctoPay. Запросы в CashUp выполняет
только backend OctoPay с межсервисной подписью. Не передавать JavaScript-фронтенду
общий секрет интеграции, токен сессии CashUp, id клиента или карты.

Платёжная сессия хранится в HttpOnly cookie `op_cashup_checkout`, путь `/api`,
SameSite=Lax, Secure в production. Её срок — 30 минут с создания, без продления.
Фронтенд не читает cookie и не сохраняет OTP или телефон в localStorage.
Один браузер использует одну текущую NFC-сессию; переход к другой точке заменяет её.

POST выполнять с `Content-Type: application/json`, в том же origin. Межсайтовые
запросы отклоняются. Запросы имеют ограничения частоты; при 429 учитывать `Retry-After`,
если заголовок есть. OTP можно отправлять повторно не раньше чем через 60 секунд.

Сумма: число больше 0, не больше 100 000 000, максимум два десятичных знака.
В JSON передавать число, например `1000` или `10.01`. Денежные строки и `1.005` запрещены.

## API покупателя

### Информация о кассе

```http
GET /api/checkout/point?code={publicCode}
```

```json
{
  "name": "Магазин",
  "branchName": "Центральный филиал",
  "pointName": "Касса 1",
  "address": "Бишкек",
  "currency": "KGS",
  "coveragePercents": [10, 20, 30]
}
```

`address` — адрес магазина CashUp, может быть `null`. Возвращаются только проценты
в пределах текущего максимума магазина. Баланс до подтверждения телефона недоступен.
404 означает недоступную/отключённую точку или закрытый филиал; 409 — неготовую интеграцию.

### Восстановить состояние

```http
GET /api/checkout/session
```

Без cookie: `{ "authenticated": false }`. Для существующей сессии:

```json
{
  "authenticated": true,
  "pointCode": "public-code-from-nfc-link",
  "sessionId": "UUID",
  "expiresAt": "2026-10-02T10:30:00.000Z",
  "maskedPhone": "+996 ••• •• 56",
  "invoiceId": null
}
```

`sessionId` — идентификатор, не токен авторизации. `maskedPhone` до OTP равен `null`.
При совпадении `pointCode` и `authenticated: true` перейти к сумме без повторного OTP.
Если `invoiceId` заполнен, открыть этот счёт. Не создавать второй счёт после обновления страницы.

### Начать сессию

```http
POST /api/checkout/start

{ "pointCode": "код из NFC-ссылки" }
```

Для новой сессии ответ содержит `sessionId`, `expiresAt`; cookie выставляется сервером.
Если действующая сессия относится к той же точке, возвращается её состояние как выше.
При полученном `invoiceId` продолжить существующий счёт.
Вызов не создаёт платёжный счёт и не резервирует баллы.
При недоступности CashUp текущая сессия сохраняется; повторить запрос после восстановления связи.

### Запросить OTP у CashUp

```http
POST /api/checkout/otp-request

{ "phone": "+996700123456" }
```

```json
{ "ok": true, "expiresInSeconds": 300 }
```

Сначала нужен `/start`. OTP — 6 цифр, срок 5 минут, максимум 5 неверных попыток
на выданный код. Код оплаты отделён от кода входа в приложение CashUp.
До успешного подтверждения можно изменить номер и запросить новый код.
После подтверждения для смены номера нужна новая сессия.

### Подтвердить OTP

```http
POST /api/checkout/otp-verify

{ "code": "123456" }
```

```json
{
  "authenticated": true,
  "maskedPhone": "+996 ••• •• 56",
  "available": 1500,
  "expiresAt": "2026-10-02T10:30:00.000Z"
}
```

CashUp проверяет код, существующую карту, её статус и доступность баланса.
Здесь нет регистрации, выдачи новой карты или замены сессии мобильного приложения.
После сетевого сбоя повтор с тем же кодом и сессией допускается.

### Рассчитать варианты покрытия

```http
POST /api/checkout/quote

{ "amount": 1000 }
```

```json
{
  "amount": 1000,
  "currency": "KGS",
  "available": 150,
  "options": [
    { "percent": 0, "bonusAmount": 0, "bankAmount": 1000, "available": true, "reason": null },
    { "percent": 10, "bonusAmount": 100, "bankAmount": 900, "available": true, "reason": null },
    { "percent": 20, "bonusAmount": 200, "bankAmount": 800, "available": false, "reason": "INSUFFICIENT_AVAILABLE_POINTS" }
  ]
}
```

Рисовать только полученные варианты. `0` обозначает «Без баллов».
Недоступные варианты заблокировать, объяснив `reason`:

- `INSUFFICIENT_AVAILABLE_POINTS` — недостаточно баллов;
- `AMOUNT_TOO_SMALL` — при таком проценте получается меньше одного балла.

Расчёт: `floor(сумма × процент / 100)` целых баллов; банковская часть — остаток
в тыйынах. Поэтому на дробной сумме даже при 100% может остаться дробная банковская
часть: всегда показывать обе серверные суммы, а не обещать оплату целиком баллами.
После изменения суммы запросить новый quote. Quote не резервирует баланс.

### Создать счёт

```http
POST /api/checkout/invoice

{ "amount": 1000, "coveragePercent": 20 }
```

```json
{
  "invoiceId": "1234567890123456",
  "paymentUrl": "https://payment.octopay.click/pay/1234567890123456"
}
```

В одной сессии создаётся один счёт. Повтор с той же суммой и процентом возвращает
тот же счёт. После таймаута повторять тот же запрос, не сбрасывать сессию.
Иные параметры после начала создания дают `409 IDEMPOTENCY_CONFLICT`.
Перед первым созданием сервер заново проверяет баланс и правила.
На счёте фиксируются точка, филиал, выбранный процент и получатель; поля не берутся из браузера.

### Подтвердить резерв на странице счёта

Используется существующий маршрут OctoPay:

```http
POST /api/invoices/{invoiceId}/loal/reserve

{ "amount": 200 }
```

Для самостоятельного счёта требуется cookie его подтверждённой CashUp-сессии.
Количество баллов обязано точно соответствовать сохранённой сумме и проценту.
Старая OTP-сессия OctoPay не даёт права резервировать баллы этого счёта.

```json
{
  "status": "reserved",
  "originalAmount": 1000,
  "bonusAmount": 200,
  "payableAmount": 800,
  "expiresAt": "2026-10-02T10:20:00.000Z",
  "paymentVersion": 2
}
```

При полном покрытии `status` может сразу быть `paid`. При неоднозначном ответе
обновлять состояние счёта; нельзя автоматически создавать новый платёж.
`expiresAt` этого ответа — срок резерва, обычно 15 минут. Он отличается от срока сессии/счёта.

### Отменить резерв

```http
POST /api/invoices/{invoiceId}/loal/cancel

{}
```

Отменить может только сессия, создавшая резерв. После отмены обновить счёт.
В NFC-сценарии выбранный процент сохраняется: до повторного подтверждения резерва
банковский QR блокируется. После подтверждённой банковской оплаты не предлагать отмену
или повторную оплату: дождаться окончательного статуса.

### Начать новую сессию

```http
POST /api/checkout/reset

{}
```

Ответ `{ "ok": true }`, cookie удаляется. Это **не** отмена существующего счёта или резерва.
Не использовать reset как восстановление после таймаута создания счёта/оплаты.

## Состояния страницы счёта

Обновлять `GET /api/invoices?invoiceId={invoiceId}` существующим механизмом polling.
В публичный счёт добавлены:

- `selfService: boolean`;
- `checkoutPointName`, `checkoutBranchName`: строка или `null`;
- `checkoutCoveragePercent`: число или `null`.

Внутренние UUID точки/филиала и телефон не нужны фронтенду покупателя.

| Состояние | Интерфейс |
|---|---|
| Самостоятельный счёт, процент > 0, резерв ещё не создан | Итог и явная кнопка подтверждения; без банковского QR |
| `RESERVE_PENDING`, `COMMIT_PENDING`, `CANCEL_PENDING` | Обработка, polling; без новой финансовой попытки |
| `RESERVED` | Банковская оплата остатка и сведения о резерве |
| `FAILED`, `CANCELLED`, `EXPIRED` у бонусной части | Обновить состояние; для нового резерва нужно явное подтверждение |
| `status=paid` при незавершённой бонусной части | Обработка, пока сервер не завершит обе части |
| Финальная оплата | Успех, номер счёта и разбивка |
| `partial` / `overpaid` | Использовать существующий экран сверки; не показывать обычный успех |
| Срок счёта истёк до оплаты | Счёт недоступен для новой банковской попытки |

Для определения конечного статуса переиспользовать `clientPaymentStatus`.
Не считать резерв, возврат из приложения банка или успешный HTTP-запрос доказательством оплаты.

## Управление кассами в кабинете OctoPay

Доступ: администратор бизнеса (`ADMIN`). Магазин определяется по его авторизованному
бизнесу и действующей привязке CashUp. Филиалы берутся из CashUp, не из списка UUID филиалов OctoPay.
Деньги всех точек этой интеграции поступают на основной KGS-счёт, выбранный для Loal в OctoPay.

```http
GET /api/business/checkout-points
```

```json
{
  "points": [{
    "id": "UUID",
    "name": "Касса 1",
    "branchId": "UUID",
    "publicCode": "24-character-public-code",
    "coveragePercents": [10, 20, 30],
    "isActive": true,
    "url": "https://payment.octopay.click/s/24-character-public-code"
  }],
  "branches": [{ "id": "UUID", "name": "Центральный филиал" }]
}
```

```http
POST /api/business/checkout-points

{ "name": "Касса 1", "branchId": "UUID филиала CashUp", "coveragePercents": [10, 20, 30] }
```

Успех: `201`, `{ "id": "UUID" }`, затем обновить список.
От 1 до 20 целых процентов в диапазоне 1–100; каждый не выше максимума магазина.
Повторы процентов убираются, список сортируется. 0 добавляется к quote автоматически.
В этой версии название, филиал и список процентов задаются при создании точки.
Для другой конфигурации создать новую точку и отключить старую.

```http
PATCH /api/business/checkout-points

{ "id": "UUID точки", "isActive": false }
```

Успех: `{ "ok": true }`. На NFC записывать `url`, такой же URL кодировать в QR.
Ссылка общая, постоянная; индивидуальные счета создаются после подтверждения клиентом.
Отключение точки запрещает новые сессии и резервы, но не отменяет уже принятые платежи.

## Учёт и кассир CashUp

`GET /admin/v1/merchants/{merchantId}/client-payments` дополнен полями:
`source` (`merchant` / `self_service`), `branchId`, `checkoutPointId`,
`bonusAmount`, `bankAmount`. До финального события суммы частей могут быть `null`.

Кассир видит собственные выставленные счета и самостоятельные оплаты назначенных
ему филиалов; администратор филиала — свои филиалы; владелец — весь магазин.
У самостоятельной оплаты нет фиктивного сотрудника-эмитента. Филиал записывается
в журнал списания после финального подписанного события без повторного списания баллов.
Кассир сверяет номер счёта, полную сумму покупки и финальный серверный статус.

Для кабинета CashUp также доступны:

- `GET /admin/v1/merchants/{merchantId}/checkout-points`;
- `POST /admin/v1/merchants/{merchantId}/checkout-points` с теми же полями создания;
- `PATCH /admin/v1/merchants/{merchantId}/checkout-points/{pointId}` с `{ "isActive": false }`.

Эти настройки доступны владельцу магазина и агентству.

## Ошибки

API `/api/checkout/*` возвращает `{ "error": "текст", "code": "КОД" }` для
ошибок CashUp. Локальные ошибки валидации могут содержать только `error`.

| HTTP / code | Действие |
|---|---|
| 401 `CHECKOUT_SESSION_EXPIRED` | Предложить заново подтвердить клиента; уже оплаченный счёт не оплачивать повторно |
| 401 `CHECKOUT_OTP_REQUIRED` | Экран телефона и OTP |
| 401 `OTP_INVALID` / `OTP_EXPIRED` | Исправить код / запросить новый |
| 429 `OTP_RATE_LIMITED` / `OTP_TOO_MANY_ATTEMPTS` | Показать ожидание и возможность повторного запроса |
| 404 `CARD_NOT_FOUND` | Карта CashUp не найдена; не создавать аккаунт OctoPay |
| 409 `CARD_FROZEN` | Карта недоступна для списаний |
| 409 `CHECKOUT_OPTION_UNAVAILABLE` | Обновить quote, предложить доступный процент |
| 409 `IDEMPOTENCY_CONFLICT` | В этой сессии уже фиксированы другие параметры счёта |
| 404 `CHECKOUT_POINT_UNAVAILABLE` | Касса/филиал отключены |
| 409 `OCTOPAY_NOT_READY` | Магазин должен проверить интеграцию и основной KGS-счёт |
| 502/503 | Повторить тот же запрос; для операций со счётом сначала обновить его состояние |

## Backend и выкладка

CashUp: новая миграция `core/0027_self_checkout.sql`, обновления core-service,
auth-service, card-service и gateway. Core должен знать `AUTH_SERVICE_URL`.
Используется настроенная доставка WhatsApp CashUp (`whatsappId`, `WHATSAPP_OTP_BASE_URL`).
`OTP_BYPASS_CODE` допустим только в локальных/CI тестах.

OctoPay: Prisma-миграция `20261002100000_self_checkout`, генерация Prisma Client,
обновление приложения. Используются `CASHUP_BASE_URL` и `CASHUP_BONUS_API_SECRET`;
значение последнего совпадает с `OCTOPAY_BONUS_API_SECRET` CashUp.
Для выдачи платёжного счёта сохраняется существующая обратная интеграция и её ключ подписи.
`OCTOPAY_CHECKOUT_BASE_URL` CashUp опционально переопределяет origin NFC-ссылок;
по умолчанию — `https://payment.octopay.click`.
Прокси платёжного домена должен пропускать `/s/*`, `/pay/*`, `/api/checkout/*`
и используемые API счёта/банков в OctoPay, сохраняя `Host` и `X-Forwarded-Proto`.

Сначала выкатить совместимые миграции и backend обеих систем, затем включать точки.
Существующий cron сверки Loal и доставки финальных событий OctoPay должен работать.
Просроченные платёжные сессии CashUp удаляются фоново спустя сутки; финансовая история сохраняется.

При проверке на пустой базе обнаружена существующая проблема истории Prisma OctoPay:
`20250124_admin_panel` обращается к таблице `Business` до её создания. Исторические
миграции здесь не изменены. Новая миграция NFC отдельно проверена на схеме текущей
версии OctoPay; полный `migrate deploy` с нуля требует отдельного исправления baseline.
