# 07 — Web-кассиры филиала

## Что готово на backend

Партнёр теперь считается администратором своего филиала и может создать отдельный
OTP-аккаунт кассира по имени и телефону. Филиал назначает сервер из аккаунта партнёра.
Кассир не получает доступ к настройкам, сотрудникам, клиентской базе и данным владельца.

Его web-кабинет состоит из трёх разделов:

1. обзор филиала и состояния подписки — `GET /v1/cashier/overview`;
2. списание бонусов — существующий `POST /v1/redemptions`;
3. собственная история списаний — `GET /v1/cashier/redemptions`.

Управление кассирами партнёром:

```http
GET    /admin/v1/members/{partnerMemberId}/cashiers
POST   /admin/v1/members/{partnerMemberId}/cashiers
DELETE /admin/v1/members/{partnerMemberId}/cashiers/{cashierMemberId}
```

Тело создания:

```json
{ "fullName": "Айжан К.", "phone": "+996700123456" }
```

После создания кассир входит через общий OTP-flow. После удаления его текущая сессия
немедленно перестаёт работать. Полный формат запросов, ответов и ошибок находится в
[`docs/API.md`](../../API.md#web-кассир-филиала).

Созданный заранее номер не считается ошибкой «уже зарегистрирован». До первого OTP-входа
у строки `registrationStatus: "pending"`, после — `"registered"` и заполненный
`registeredAt`. При обнаружении перехода показать toast «Кассир зарегистрировался».

## Что сделать во фронте

- В кабинете партнёра добавить список и форму создания кассиров.
- Не показывать выбор филиала: backend назначает филиал автоматически.
- Для роли `partner_employee` открывать отдельный узкий layout кассира.
- В overview отображать название филиала, магазина, статус и дату подписки.
- В истории не ожидать телефон клиента; поддержать пагинацию, поиск и сортировку.
- В общем журнале списаний добавить колонку «Кассир» из `cashierName`; для 1С и старых
  операций значение может быть `null`, тогда показывать «—».
- После `401 SESSION_REPLACED` очистить токены и вернуть пользователя на OTP-вход.

## Проверочный сценарий

1. Партнёр создаёт кассира с новым номером.
2. Кассир входит по OTP и видит только свой филиал и подписку.
3. Кассир списывает бонусы через `/v1/redemptions`.
4. Операция появляется в его истории и не раскрывает телефон клиента.
5. Кассир получает `403` при попытке создать другого кассира.
6. Партнёр удаляет кассира; старый access token получает `401`.
