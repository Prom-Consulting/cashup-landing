# Новое для веб-фронтенда

Что приходит этим обновлением бэкенда и что сделать во фронте (`cashup-landing`).
Работает на проде после ближайшего деплоя; полный контракт — в [API.md](../../API.md).

| # | Что | Где во фронте |
|---|---|---|
| 1 | Код из WhatsApp вводится один раз | `packages/app-kit/src/phone-sign-in.tsx` |
| 2 | Промокоды | admin — новая страница; partner и client — поле ввода |
| 3 | Занятая почта в профиле — `409` | формы профиля |
| 4 | Хранилище кодов недоступно — `503` | экран входа |

## 1. Код из WhatsApp вводится один раз

**Было:** `POST /auth/login` по телефону с новым номером отвечал `401` и **гасил код**.
Поэтому `phone-sign-in.tsx` запрашивал второй код («Номер новый — создадим вам аккаунт.
Отправили ещё один код…») и звал `registerByPhone`. Клиент вводил два разных кода.

**Стало:** код проверяется один раз, сервер сам решает — войти или создать аккаунт.

```
POST /auth/login     { "phone": "...", "otp": "123456", "deviceId": "..." }
POST /auth/register  { "phone": "...", "otp": "123456", "deviceId": "..." }
→ 201 { "accessToken": "...", "expiresIn": "12h", "isNewAccount": true | false }
```

- `/auth/login` с новым номером **создаёт** аккаунт — `isNewAccount: true`;
- `/auth/register` с известным номером **входит** — `isNewAccount: false`; `409` больше нет.

**Что сделать:**
1. В `phone-sign-in.tsx` оставить один вызов `loginByOtp`. Ветку с повторным `requestOtp`
   и `registerByPhone` (около строк 100–122) удалить — она больше не срабатывает.
2. Добавить `isNewAccount` в `authTokensSchema` (`packages/api/src/schemas/auth.ts`)
   необязательным полем — вход по почте его не присылает. `true` — показать приветствие.

## 2. Промокоды web/admin

Важно: клиентский mobile v2 не использует помесячную подписку, `months`
и `POST /v1/me/promo-code`. Ниже сохранён контракт web/admin; секция 2.3
является legacy и не является задачей для нового mobile.

Оператор создаёт промокод на N бесплатных месяцев подписки — **для магазинов** или
**для клиентов**. Код многоразовый: им пользуется сколько угодно магазинов или клиентов,
но каждый — один раз. Регистр не важен: `summer-2026` и `SUMMER-2026` — один код.

### 2.1. Админка (`apps/admin`) — новая страница «Промокоды»

Только агентство (`super_admin`), остальным `403`.

```
GET    /admin/v1/promo-codes?audience=merchant|client&includeDeleted=true
POST   /admin/v1/promo-codes
PATCH  /admin/v1/promo-codes/{id}
DELETE /admin/v1/promo-codes/{id}
GET    /admin/v1/promo-codes/{id}/redemptions
```

**Создать** — `POST /admin/v1/promo-codes`:

| Поле | Тип | Обязательно | Правило |
|---|---|---|---|
| `code` | string | нет | 4–32 символа: латиница, цифры, дефис. Не прислать — сервер сгенерирует `LOAL-XXXXXX` (без похожих 0/O, 1/I/L). Хранится заглавными |
| `audience` | `"merchant"` \| `"client"` | да | Магазинам (подписка магазина) или клиентам (подписка карты) |
| `months` | integer | да | 1–36 бесплатных месяцев |
| `maxUses` | integer \| null | нет | Лимит применений; `null` — без лимита |
| `expiresAt` | ISO-дата \| null | нет | Действует до; `null` — бессрочно |
| `note` | string \| null | нет | Заметка, до 200 символов |

Ответ — промокод (такой же объект в списке):

```json
{ "id": "...", "code": "SUMMER-2026", "audience": "merchant", "months": 2,
  "maxUses": 100, "uses": 7, "expiresAt": null, "active": true,
  "note": "летняя акция", "createdAt": "..." }
```

Код уже существует — `409`. Лишнее поле — `400` с его названием.

**Изменить** — `PATCH /admin/v1/promo-codes/{id}` с любыми из
`{ "active", "maxUses", "expiresAt", "note" }`. `active: false` — код перестаёт
применяться. `months` и `audience` не меняются — выпустить новый код.

**Удалить** — `DELETE /admin/v1/promo-codes/{id}` → `{ "deleted": true }`. Код пропадает
из списка (увидеть — `?includeDeleted=true`), история применений остаётся.

**Кто применил** — `GET /admin/v1/promo-codes/{id}/redemptions`:

```json
[{ "id": "...", "merchantId": "...", "merchantName": "Кофе Хаус",
   "userId": null, "userPhone": null, "months": 2, "createdAt": "..." }]
```

У клиентского кода вместо магазина — `userId` и `userPhone`.

**Экран:** таблица — код (кнопка «Скопировать»), кому, месяцев, использовано
`uses / maxUses`, срок, активен (переключатель), удалить; кнопка «Создать промокод» с
формой по таблице полей; по строке — список «кто применил».

### 2.2. Кабинет партнёра (`apps/partner`) — поле «Промокод»

Рядом с подпиской магазина.

```
POST /admin/v1/merchants/{merchantId}/promo-code
{ "code": "SUMMER-2026" }
→ 201 { "code": "SUMMER-2026", "audience": "merchant", "months": 2,
        "subscription": { "merchantId": "...", "expiresAt": "2026-12-27T...", "isActive": true } }
```

Месяцы добавляются к подписке магазина — к более поздней из дат «сегодня» и «текущий
конец». После успеха перезапросить подписку магазина. Применяет только владелец
магазина (роль `admin` в `merchants[]` токена); кассиру и партнёру-продавцу `403` — поле
им не показывать.

### 2.3. Legacy web-кабинет клиента — не для mobile v2

В настройках.

```
POST /v1/me/promo-code
{ "code": "LOAL-7KX2QM" }
→ 201 { "code": "LOAL-7KX2QM", "audience": "client", "months": 1,
        "subscription": { "status": "active", "periodsTotal": 4, "periodsGranted": 1,
                          "currentPeriodEnd": "...", ... } }
```

Месяцы ложатся на подписку карты как оплаченные: подписки не было — начинается сразу с
выдачей бонусов; есть — месяцы добавляются. После успеха перезапросить `GET /v1/me/card`.

### 2.4. Ошибки применения

| Код | Когда | Текст |
|---|---|---|
| `400` | Не та аудитория, истёк, закончились использования, неверный формат | из `message` |
| `404` | Код не найден, выключен или удалён | «Промокод не найден» |
| `404` | Клиент без карты (`message` начинается с «Сначала получите карту») | «Сначала получите карту» + «Купить подписку» |
| `409` | Этот магазин / клиент уже применял этот код | «Вы уже использовали этот промокод» |
| `502` | Клиент: сервис карт не ответил — код не засчитан | «Попробуйте ещё раз» |

## 3. Профиль: занятая почта — `409`

`PUT /auth/me { "email": "..." }` с почтой другого аккаунта раньше падал в `500`, теперь
отвечает `409` «Эта почта уже используется другим аккаунтом». Показать у поля почты.

## 4. Хранилище кодов недоступно — `503`

Коды из WhatsApp теперь хранятся в Redis и переживают деплой: код, отправленный до
обновления сервера, после него всё ещё действует. Если хранилище недоступно,
`POST /auth/otp/request` и вход по коду отвечают `503` «Сервис кодов временно
недоступен» — показать «Попробуйте через минуту», а не «неверный код».

## 5. Телефон — только с кодом страны

Сервер больше не угадывает страну номера. Раньше клиентов сравнивали по последним девяти
цифрам, и киргизский `+996 770 123 456` совпадал с казахстанским `+7 777 012 3456`.
Теперь номер без кода страны (`0700 123 456`, `8 701 …`) и несуществующий номер
отвечают `400` «Укажите номер с кодом страны, например +996700123456».

Касается всех полей телефона: вход и регистрация, выдача карты и «Добавить клиента» в
админке, самозапись по QR, оплата подписки по телефону, оплата партнёру
(`clientPhone`). Во фронте — маска или выбор страны с `+996` по умолчанию, и текст из
`message` показать у поля.

Сервер отдаёт номер цифрами с кодом страны, без `+`: `996700123456`.

«Добавить клиента» (`POST /admin/v1/customers`) с номером, который уже есть у другого
клиента, теперь отвечает `409` «Клиент с телефоном … уже есть» — показать у поля
телефона.

## 6. Управление магазином — только владельцу

Раньше любой, кто работает в магазине, мог всё: кассир выдавал магазину бесплатные месяцы,
назначал администраторов и видел токен 1С. Теперь адреса `/admin/v1/merchants/{id}/…`
проверяют роль человека в этом магазине (`merchants[].role` в токене):

- **все роли** — только просмотр магазина, профиля, потолка процента, филиалов и настроек
  кассы;
- **владелец (`admin`)** — всё остальное: сотрудники и партнёры, 1С, вебхуки, продажи и
  журнал списаний, счета и подписка, правка профиля, потолка, филиалов, настроек кассы,
  промокод магазина;
- **только агентство** — выдать магазину месяцы без оплаты, переименовать.

Кассиру (`staff`) и партнёру-продавцу (`partner`, `partner_employee`) эти разделы и
кнопки не показывать: сервер ответит `403` «Это действие доступно только владельцу
магазина». Полная таблица — в [API.md](../../API.md), раздел «Кабинет магазина → Кто что может».

Роль в токене обновляется при следующем входе: если человеку поменяли права, пусть
перезайдёт.

## 7. Цены — на экране супер-админа, счёт магазину считает сервер

**Экран цен (admin).** `GET/PATCH /admin/v1/platform-settings` теперь отдаёт и принимает
две цены, целые сомы за месяц: `merchantAccessPriceKgs` — доступ магазина,
`cardSubscriptionPriceKgs` — подписка клиента. Два поля ввода и «Сохранить»; новая цена
действует со следующего счёта. Смена цены видна в журнале действий.

**Оплата у владельца магазина.** `POST /admin/v1/merchants/{id}/payments` принимает
только `{ "months": N }` — сумму сервер считает сам. Раньше в теле была `amount`:
теперь любое лишнее поле — `400`, его надо убрать из запроса. Показать владельцу выбор
месяцев и, если нужно, «итого» — цену можно взять только у агентства, поэтому сумму
лучше показывать из ответа (`amount`) перед переходом на `paymentUrl`.
