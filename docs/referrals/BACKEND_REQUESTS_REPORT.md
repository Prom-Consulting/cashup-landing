## P0

### 1. Красный CI и PROF-01

PROF-01 повторно проверен полным smoke-тестом. Все сценарии удаления аккаунта проходят:

- `DELETE /auth/me` без тела возвращает `204`;
- access token удалённой сессии больше не принимается;
- повторное удаление идемпотентно;
- профиль превращается в обезличенный tombstone;
- карта отзывается и отвязывается от аккаунта;
- история, подписка, реферальный профиль и начисления удаляются;
- тот же телефон может создать новый аккаунт без доступа к старой карте.

В CI добавлен вывод последних строк логов сервисов при падении smoke-теста. Это не меняет
успешный pipeline, но сохраняет диагностику вместо одного ответа `503`.

### 2. Первая покупка подписки v2 без карты

- `GET /v1/me/subscription/offer` для аккаунта без карты теперь возвращает доступный offer с
  `intent: "initial"`.
- `POST /v1/me/subscription/payments` при отсутствии карты создаёт/находит клиента по телефону
  аккаунта, выпускает платформенную карту и затем создаёт v2-платёж.
- Старая помесячная схема с `months` для этого потока не используется.
- Если у аккаунта отсутствует телефон, возвращается `400` с `error: "PHONE_REQUIRED"`.

## P1

### 3. Стабильные коды ошибок

Добавлены машинные коды, при этом HTTP-статусы и человекочитаемый `message` сохранены:

| Сценарий | `error` |
|---|---|
| Неверный OTP | `OTP_INVALID` |
| OTP отсутствует или истёк | `OTP_EXPIRED` |
| Превышено число попыток | `OTP_TOO_MANY_ATTEMPTS` |
| Повторный запрос OTP раньше срока | `OTP_RATE_LIMITED` + `retryAfter` |
| Хранилище OTP недоступно | `OTP_UNAVAILABLE` |
| Для промокода нужна карта | `CARD_REQUIRED` |

| Не та аудитория | `PROMO_WRONG_AUDIENCE` |
| Промокод истёк | `PROMO_EXPIRED` |
| Лимит промокода исчерпан | `PROMO_EXHAUSTED` |
| Промокод уже применён | `PROMO_ALREADY_USED` |
| Slug заведения занят | `MERCHANT_SLUG_TAKEN` |
| Телефон клиента занят | `CUSTOMER_PHONE_TAKEN` |
| Email аккаунта занят | `EMAIL_TAKEN` |
| Лимит покрытия пока нельзя менять | `COVERAGE_LIMIT_LOCKED` + `nextChangeAt` |

### 4. Публичный offer подписки

Добавлен публичный endpoint без авторизации:

```http
GET /v1/public/subscription/offer
```

Ответ:

```json
{
  "planId": "loal-90d-v1",
  "price": 990,
  "currency": "KGS",
  "cycleDays": 90,
  "cycleBalance": 15000
}
```

Цена берётся из настроек платформы, а не из frontend-константы.

### 5. Телефон в профиле

`GET /auth/me/profile` теперь возвращает поле `phone`. Хранить номер входа в
`localStorage` для заполнения формы больше не требуется.

### 6. Logout с отзывом сессии

Добавлен:

```http
POST /auth/logout
Authorization: Bearer <access token>
```

Успешный ответ — `204`. Backend отзывает серверную сессию, поэтому связанные access и refresh
token перестают проходить проверку. Клиент после `204` удаляет локальные токены.

### 7. `paymentId` в return URL

Для v2-платежа UUID создаётся до запроса в OctōPAY. В `return_url` добавляется
`paymentId`, например `/payment/return?paymentId=<uuid>`. Этот же UUID возвращается как ID
платежа и сохраняется в БД.

## P2

### 8. Название Loal в счетах

В legacy-счетах клиентской и партнёрской подписки, а также в имени получателя заменено
`Cashup` на `Loal`.

### 9. Адрес и координаты заведения

В профиль заведения и публичную витрину добавлены:

- `address: string | null`;
- `lat: number | null` в диапазоне `-90..90`;
- `lng: number | null` в диапазоне `-180..180`.

`lat` и `lng` при обновлении передаются только вместе. Старые клиенты могут не отправлять
новые поля: существующие значения тогда сохраняются.

### 10. Revalidation каталога

Backend выполняет best-effort `POST` на `CATALOG_REVALIDATE_URL` после изменений, влияющих
на витрину: профиль, лимит покрытия, статус/удаление заведения и изменение подписки. Таймаут —
5 секунд. Ошибка revalidation логируется, но не отменяет уже сохранённую бизнес-операцию.

В production-конфигурации адрес по умолчанию:
`https://loal.kg/api/revalidate-partners`. В локальной среде вызов выключен пустым значением.

### 11. Клиентский промокод и v2

**Требуется продуктовое решение.** Текущий endpoint `POST /v1/me/promo-code` продолжает
продлевать legacy-подписку на месяцы. Необходимо выбрать один контракт:

1. промокод запускает новый бесплатный 90-дневный цикл и устанавливает баланс 15 000;
2. промокод продлевает действующий v2-цикл без сброса текущего остатка;
3. клиентские промокоды отключаются для v2.

До решения поведение намеренно не изменено, чтобы не начислить клиентам неверный срок или
баланс.

production. Секреты и их значения в этот отчёт не копировались.

- удалить пустые дубли APNs-переменных;
- удалить устаревшие переменные цен после проверки production-конфигурации.
