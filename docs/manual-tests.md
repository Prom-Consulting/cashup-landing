# Ручные проверки: заведения, заявки, номера, Google, OctōPAY

Тестовые номера, суперадмин. Где фронта ещё нет — через API (`docs/API.md`).
Каждый пункт: действие → что должно быть.

## 1. Заявка с лендинга
- [ ] Заявка «Только Loal» → «готово, ждёт проверки». В админке: заведение `pending_review`, у него `application.plan = loyalty`.
- [ ] Отправить ту же форму ещё раз с теми же данными → та же заявка, без ошибки.
- [ ] Поменять название, отправить → отказ (номер уже занят).
- [ ] Заявка с номера кассира другого заведения → отказ.
- [ ] Заявка с номера владельца живого заведения → отказ.
- [ ] «Loal + OctōPAY» до одобрения → пароль OctōPAY не спрашивают, ссылки на OctōPAY нет.
- [ ] Одобрить её → через несколько секунд появилась ссылка на OctōPAY, в OctōPAY есть аккаунт, вход по номеру и паролю из заявки.
- [ ] «Loal + OctōPAY» с номера, у которого уже есть аккаунт OctōPAY без связи → после одобрения привязан старый аккаунт, пароль не спрашивают, вход со старым паролем.
- [ ] «Loal + OctōPAY» с номера, чей аккаунт OctōPAY связан с другим заведением → после одобрения в админке `octopayState: blocked`, причина `ACCOUNT_LINKED_ELSEWHERE`. На лендинге пароль не спрашивают.
- [ ] То же для номера, чей аккаунт OctōPAY удалён меньше 30 дней назад → `blocked`, `ACCOUNT_PENDING_DELETION`.
- [ ] «Только OctōPAY» → работает как раньше.

## 2. Отклонение заявки
- [ ] Отклонить заведение «ждёт проверки» с причиной → статус «отклонено», заведение в архиве, владельцу пришёл WhatsApp с причиной.
- [ ] Отклонить без причины → ошибка.
- [ ] Нажать «отклонить» повторно → без ошибки, причина прежняя.
- [ ] Отклонить уже одобренное заведение → отказ.
- [ ] После отказа войти на лендинге (новый код) → снова форма. Подать заявку из той же вкладки → новая заявка принята.
- [ ] Заявка без заведения (застряла или «только OctōPAY» в процессе) видна в списке с `includeApplications`. Отклонить её → «отклонено».

## 3. Экран «Заведения»
- [ ] Статусы отображаются верно: ждёт проверки / работает / приостановлено / отклонено / удалено (с датой «можно вернуть до») / данные стёрты.
- [ ] Старый экран не сломан: карточки, поиск, «показать удалённые», страница заведения.

## 4. Один номер — одно заведение
- [ ] Создать заведение вручную на номер владельца другого живого заведения → отказ.
- [ ] Добавить кассиром человека, который уже работает в другом заведении (любая роль) → отказ.
- [ ] Удалить заведение → его номера сразу можно использовать для нового заведения или в другом как кассира.

## 5. Смена номера сотрудника (суперадмин)
- [ ] Запросить код на номер, который работает в другом заведении → отказ, код не отправлен.
- [ ] Код пришёл в WhatsApp с текстом «для смены номера в Loal».
- [ ] Повторный запрос раньше чем через минуту → «подождите N секунд».
- [ ] Неверный код → ошибка, у сотрудника прежний номер.
- [ ] Верный код → у сотрудника новый номер, та же роль и филиалы.
- [ ] Старый номер после перевхода заведения не видит. Новый номер входит в это заведение с той же ролью.
- [ ] Меняем номер владельца, совпадающий с контактным → контактный номер заведения тоже обновился.
- [ ] Владелец или кассир пытается сменить номер сам → нет доступа.
- [ ] Заведение «Loal + OctōPAY», смена контактного номера → в OctōPAY вход по новому номеру, пароль прежний.
- [ ] Номер, занятый в OctōPAY другим аккаунтом → отказ, в Loal ничего не поменялось.

## 6. Выход из программы
- [ ] Кабинет: заявка на выход «только Loal» → суперадмин одобряет → заведение удалено, вход в кабинет закрыт. В OctōPAY аккаунт работает, связь с Loal разорвана.
- [ ] Заявка «Loal + OctōPAY» → одобрить → в OctōPAY аккаунт закрыт.
- [ ] Старый кабинет (без выбора) → работает как «только Loal».
- [ ] Владелец получил WhatsApp о решении (одобрено или отклонено с причиной).

## 7. Удаление суперадмином
- [ ] Удалить без выбора → «только Loal» (аккаунт OctōPAY жив).
- [ ] Удалить с `octopay=delete` → аккаунт OctōPAY закрыт.
- [ ] Удалённое заведение: изменить, активировать, добавить сотрудника нельзя (410). Смотреть можно.

## 8. Восстановление (до 30 дней)
- [ ] Предпросмотр: список людей, кто свободен и кто занят, что будет с OctōPAY.
- [ ] Вернуть → люди, филиалы и прежний статус на месте. Старые номера входят и видят заведение.
- [ ] После возврата работает Google, привязанный у владельца до удаления.
- [ ] Вебхуки, выключенные удалением, снова активны. Выключенные владельцем — нет.
- [ ] Номер владельца занят новым заведением → вернуть без замены нельзя. Код на новый номер → вернуть с заменой → владелец с новым номером, контактный номер обновлён.
- [ ] Кассир, который ушёл в другое заведение, не вернулся и указан в «пропущенных».
- [ ] Владельца нет совсем (аккаунт удалён) → без нового владельца нельзя. С новым (номер + код) → можно.
- [ ] Отклонённое заведение вернуть → «ждёт проверки», отметки отказа нет, заявка снова видна на лендинге.
- [ ] После возврата прежняя одобренная заявка на выход в кабинете не показывается, можно подать новую. Повторное «одобрить» её не удаляет заведение.
- [ ] «Loal + OctōPAY», удалено с закрытием OctōPAY → вернуть → OctōPAY `restored`, вход в OctōPAY работает.
- [ ] Удалено «только Loal» → вернуть → OctōPAY `relink_required`. Владелец привязывает аккаунт кодом из OctōPAY.
- [ ] Заведение удалено до этой версии с закрытием OctōPAY → вернуть → `gone`, заведение без OctōPAY.
- [ ] Удалить → вернуть → удалить → вернуть: всё отрабатывает.
- [ ] Работающее заведение «вернуть» → отказ.
- [ ] Прошло 30 дней или данные стёрты → «нельзя вернуть».

## 9. Google
- [ ] Владелец привязывает Google в профиле и входит через Google.
- [ ] Номер владельца сменили → новый человек привязывает тот же Google → получилось. Старый номер через этот Google больше не входит.
- [ ] Привязать Google, который открывает другое живое заведение → отказ «привязан к другому активному заведению», чужое заведение не названо.
- [ ] Уже есть свой Google → другой не привязать, пока не отвязан первый.

## 10. Перенос аккаунта OctōPAY
- [ ] Перенести аккаунт с заведения A на B → у B связь есть, у A нет. Если у B заявка была `blocked` → стала выполненной.
- [ ] У B уже свой аккаунт → отказ `TARGET_ALREADY_LINKED`.
- [ ] Повторный перенос с A → отказ `ACCOUNT_NOT_FOUND`.
